# Offline DeFi coverage calculator

This standalone CLI reads a normalized `CoverageInput` v1 JSON file and a locally supplied reviewed-manifest JSON file. It performs no network calls, RPC, runtime authorization, or market discovery. The repository includes frozen offline source inputs and derived normalization/report evidence under [`data/defi-coverage/`](../../data/defi-coverage/); these are bounded roster/workflow observations, not a verified complete product census. Do not present synthetic test fixtures or the conservative raw-roster proxy as observed distinct protocols or complete market evidence.

Run from the repository root with the installed TypeScript runner:

```sh
npx ts-node scripts/defi-coverage/cli.ts --input <normalized-v1.json> --manifest <reviewed-manifest.json> [--output <report.json>]
npx ts-node scripts/defi-coverage/cli.ts --input <normalized-v1.json> --manifest <reviewed-manifest.json> --check <expected-report.json>
npx ts-node scripts/defi-coverage/normalize-baseline.ts
npx ts-node scripts/defi-coverage/normalize-baseline.ts --check
```

Manifest input may be a `DefiFunctionPolicy[]` or an object with a `capabilities` array. A capability counts only when active, verified with a source/date, contract-call typed, and an exact chain/address/signature/ABI-hash match for a required workflow. The normalized input independently freezes the observation universe, per-chain enumeration status, eligibility rule, product identity/category/lineage role, expected in-scope chain inventory per product, activity evidence, deployments/instances, core-workflow requirements, and expected activity metric definitions. `lineage_only` parent labels may not be counted as coverage units. Countable products require explicit expected-chain inventories and one observation for every expected chain; incomplete inventories remain in the denominator but cannot count as complete. A core workflow may use an explicitly unresolved requirement status only with a reason/source reference; it remains unsupported until requirements are resolved. Known capture time uses `observedAt`; unknown capture time must use `observedAt: null` and an explanation, and prevents a current coverage objective claim. Complete workflow or deployment enumerations cannot be empty; absent/incomplete information remains unknown and does not pass coverage.

Any unresolved universe source record blocks `identityEnumerationComplete` and the overall objective, even when its chain is known: it remains a source-row proxy rather than a verified canonical product or valid upper bound. This does not block a legitimate objective based on a fully enumerated known product universe with known canonical unresolved products (for example, 10/11 conservative coverage can pass). Weighted reports expose applicable unresolved source-proxy reference/row counts separately from known unresolved products and missing product weights. Any applicable source proxy or missing active/unresolved product weight makes the weighted conservative ratio `null` and `targetMet: false`; the observed weighted cohort ratio remains based on its positively observed weighted cohort. Proxy rows with known chain/category affect only matching groups; missing chain or category attribution may affect every compatible group.

`normalize-baseline.ts` is the deterministic offline adapter for the frozen `market-snapshot.json`, `discovery-classification.json`, and `workflow-baseline.json` plus the reviewed production manifest. It writes `normalized-baseline.json`, `coverage-baseline-report.json`, and `normalization-evidence.json` in `data/defi-coverage/`; `--check` recomputes and byte-compares all three without writing. It makes no network/RPC calls and reads no wall clock. The evidence output retains the full 8,476-row raw roster and metric observations, classification rules/counts, workflow source inventory, and source-file digests. Raw roster rows stay unresolved conservative proxy records (not verified unique products); product candidates remain lineage-only. The unavailable UTC capture time stays null. Market metrics are not promoted to activity weights without compatible product/chain/window attribution. Workflow bindings are accepted only through exact seed capability ID, chain, target, signature, and ABI hash matches against active verified manifest capabilities. The workflow seed contains 16 product candidates and 35 source workflow records (172 product-assigned exact IDs and seven additional Velodrome IDs at an observed target whose raw version remains unassigned); it is not a product denominator.

The current derived report records zero positively evidenced canonical active-product rows, observed coverage as `null`, 8,476 unresolved raw-roster proxy rows for conservative accounting, and `objectiveEstablished: false`. This does not assert there are no active products: the proxy rows are not verified distinct protocols/products, and source capture UTC, complete chain enumeration, canonical identity, and compatible 90-day product activity evidence remain unresolved. `observedAt` is null; the parent's artifact-existence check at `2026-10-03T16:59:58Z` is only an upper bound on file existence, not the API capture time. The local reported date `2026-10-04` is not converted to UTC. The normalized report includes 57 workflow rows, 50 complete at their mapped evidence scope and 7 unresolved/source-blocked; these do not count complete products. The adapter and report demonstrate offline normalization tooling only. **M1 Oracle Gate 1 passed on attempt 2/3 after R1/R2 closure; separately, the final market-coverage objective remains unestablished.** Completing M1 does not imply reaching the final 90% coverage target.

The report uses integer basis points and returns `null` for zero denominators. It includes a SHA-256 fingerprint of the normalized input and relevant manifest capability identities; `--check` compares the recomputed stable JSON byte-for-byte with the supplied report. It exposes active-cohort and conservative ratios, chain/category breakdowns, complete workflow-definition inventory (including unresolved definitions), per-product/chain workflow and instance completeness, per-instance capability failures with source references, unresolved universe records, and compatible activity-weighted groups only. Unknown source records count once globally by source reference and once in each chain to which explicitly attributed; null-chain records are retained globally, shown separately per chain, and suppress per-chain conservative ratios/objective claims. Those source rows are conservative proxy units, not verified distinct protocol products. Activity weights are never combined across different chains, categories, definitions, units, windows, or sources. Missing activity values remain counted as missing and block a weighted target pass. Objective establishment requires complete scope-chain and product-chain inventory, known capture time, and met observed/conservative targets. A passing percentage is not evidence of financial suitability, runtime security, liquidity, deployment, transaction success, or permission to transact.
