# Operator wallet provisioning recovery

This deliberately narrow recovery tool only binds a known, already-created Openfort Developer-custody EVM account to the wallet and provisioning intent identified by the operator. It verifies the raw v2 account-list record (including explicit `chainType`, custody, ID, and address); it does not infer missing fields from the high-level EVM account getter. It is not an API or frontend capability. It never calls a provider create operation, retries a creation, or resets an intent automatically.

Run `npx ts-node scripts/recover-wallet-provisioning.ts --wallet-id <uuid> --dispatch-token <token> --account-id <provider-id> --operator <identifier> --evidence <ticket-or-evidence-ref> [--expected-address <address>]`. Configure `DATABASE_URL`, `OPENFORT_API_KEY`, and `OPENFORT_WALLET_SECRET` in the environment. Do not put secrets in arguments. The CLI emits no provider payloads or secrets.

Before using this command, independently establish that the provider account is the original dispatch result and belongs to this intent. The tool scans the raw account list in bounded pages and fails closed if the result is malformed, truncated, or exceeds its safe scan limit. A provider listing that does not show an account is not proof that a create cannot still complete. **Safe restart/retry is not available** absent authoritative proof that the original create cannot execute and confirmation that all workers that could execute it are quiesced. This tool offers no reset/retry action. Any mismatch or CAS conflict fails closed without committing wallet, intent, or audit changes.
