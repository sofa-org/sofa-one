# DeFi registry

Registry contracts are immutable fragments of nested `chain -> contract -> function` capability catalog data. A reviewed manifest exposes exactly `{ chains, capabilities, manifestHash }`; no deployment, asset, market, pool, feed, or runtime-evidence inventory is part of authorization. `buildReviewedManifest` merges family fragments, rejects duplicate IDs/selectors and inconsistent hierarchy/ABI, validates fixed ABI identity and source/date provenance, and deep-freezes a cloned result. Active entries require verified source provenance; unverified entries remain inactive. ABI identity is Keccak-256 of recursively key-sorted ABI JSON (array order preserved). Catalog identity hash sorts capability IDs and binds ID/type/chain/normalized address/signature/ABI hash/status while excluding descriptions and provenance dates. The pinned catalog has 202 definitions (179 actions, 23 separately grantable approvals): the preserved pre-generator snapshot hash is `0x43ec3be0b20a32457719d8edb17c8eaa40c93480921d6e7c86e9c2cacdec5897`. Static source input, independent full baseline fixture, and deterministic generator/check/diff are documented in [M1 catalog tooling status](../../../../docs/defi-research/majority-catalog-tooling.md). The previous protocol-expansion source/admission review is not the separate pending M1 generator/coverage gate. No deployment, runtime code identity, liquidity, or funded-execution proof is implied.
