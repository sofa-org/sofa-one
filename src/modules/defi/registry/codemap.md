# DeFi registry

Registry contracts are immutable fragments of nested `chain -> contract -> function` capability catalog data. A reviewed manifest exposes exactly `{ chains, capabilities, manifestHash }`; no deployment, asset, market, pool, feed, or runtime-evidence inventory is part of authorization. `buildReviewedManifest` merges family fragments, rejects duplicate IDs/selectors and inconsistent hierarchy/ABI, validates fixed ABI identity and source/date provenance, and deep-freezes a cloned result. The static production catalog has 349 definitions (326 actions, 23 separately grantable approvals) across seven aggregate chain IDs. It preserves all 315 v2 definitions and adds 34 v3 functions (28 NPM functions and six Morpho Blue functions); all 13 new execution scopes bind seven exact NPM multicall child sets and six empty-callback Morpho methods. Scope hashes are part of executable identity, while profile copy/status overlays are not. Nine version 1.0.0 bundles contain 75 unique exact IDs and are verified against the generated manifest; they do not automatically assign grants. The final mandatory M3 gate remains pending. This is not deployment, runtime-code identity, liquidity, financial validation, or funded-execution proof. See [v3 catalog and bundle review](../../../docs/defi-research/majority-catalog-v3.md) and the [capability matrix](../../../docs/defi-capability-matrix.md).
