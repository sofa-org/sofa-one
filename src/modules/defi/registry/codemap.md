# DeFi registry

Registry contracts are immutable fragments of nested `chain -> contract -> function` capability catalog data. A reviewed manifest exposes exactly `{ chains, capabilities, manifestHash }`; no deployment, asset, market, pool, feed, or runtime-evidence inventory is part of authorization. `buildReviewedManifest` merges family fragments, rejects duplicate IDs/selectors and inconsistent hierarchy/ABI, validates fixed ABI identity and source/date provenance, and deep-freezes a cloned result. Active entries require verified source provenance; unverified entries remain inactive. ABI identity is Keccak-256 of recursively key-sorted ABI JSON (array order preserved). Catalog identity hash sorts capability IDs and binds ID/type/chain/normalized address/signature/ABI hash/status while excluding descriptions and provenance dates. The v1 baseline retains 202 definitions (179 actions, 23 separately grantable approvals) and manifest hash `0x43ec3be0b20a32457719d8edb17c8eaa40c93480921d6e7c86e9c2cacdec5897`. The M2 static v2 catalog preserves those definitions exactly and adds 113 source-qualified functions under explicit family-version IDs; admissions bind exact ABI/function identity to canonical digests of the two frozen source snapshots. Source-compiler candidates remain inactive unless an exact admission binding is present. Existing grants are not rewritten or auto-assigned. M1 Oracle gate passed separately; M2 final review/integrated validation remains parent-owned. No deployment, runtime code identity, liquidity, financial validation, or funded-execution proof is implied.
