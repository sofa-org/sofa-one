# DeFi registry

Registry contracts are immutable fragments of nested `chain -> contract -> function` capability catalog data. A reviewed manifest exposes exactly `{ chains, capabilities, manifestHash }`; no deployment, asset, market, pool, feed, or runtime-evidence inventory is part of authorization. `buildReviewedManifest` merges family fragments, rejects duplicate IDs/selectors and inconsistent hierarchy/ABI, validates fixed ABI identity and source/date provenance, and deep-freezes a cloned result. Active entries require verified source provenance; unverified entries remain inactive. ABI identity is Keccak-256 of recursively key-sorted ABI JSON (array order preserved). Catalog identity hash sorts capability IDs and binds ID/type/chain/normalized address/signature/ABI hash/status while excluding descriptions and provenance dates. Production assembly currently contains 202 active functions: the preserved prior 108 (88 actions, 20 canonical approvals) plus 94 additions (91 actions: 4 SparkLend, 27 Venus, 60 SushiSwap V2; and 3 separately grantable ERC-20 approvals for Ethereum DAI and BNB Chain BTCB/ETH). The 23 canonical approvals comprise the prior 20 and these three explicit grants; no approval is automatic or action-dependent. Counts record catalog admission only, not deployment, runtime code identity, liquidity, or funded execution proof.
