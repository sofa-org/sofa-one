# DeFi capability operations and limitations

The current static catalog contains **315 active exact function definitions** across seven supported chain IDs: 292 actions and 23 independently grantable canonical `approve(address,uint256)` functions. It preserves the complete 202-definition v1 baseline (179 actions, 23 approvals) unchanged and adds 113 source-qualified functions: Uniswap V3 NonfungiblePositionManager (7 target rows × 5 fixed lifecycle methods = 35), Balancer V2 Vault (6 × 4 fixed methods = 24), Aave V3 Pool (3 × 4 = 12), Compound III Comet (10 × 2 = 20), and Compound V2 (4 CToken markets plus Unitroller = 22). The counts are exact function definitions, not protocols or proof each family spans all seven chains. See the [capability matrix](../../../docs/defi-capability-matrix.md), [M2 delivery and coverage status](../../../docs/defi-research/majority-m2-delivery.md), frozen [v2 DEX sources](../../../data/defi-catalog/v2/sources/dex.json), [v2 lending/yield sources](../../../data/defi-catalog/v2/sources/lending-yield.json), and [source admission bindings](../../../data/defi-catalog/v2/admissions.json), plus the historical [baseline provenance](../../../docs/defi-research/simple-catalog-provenance.md), [DEX expansion](../../../docs/defi-research/expansion-dex-provenance.md), [Sushi V2](../../../docs/defi-research/expansion-2-sushi-provenance.md), [Spark/Venus](../../../docs/defi-research/expansion-2-lending-provenance.md), and [Rocket Pool](../../../docs/defi-research/expansion-2-rocket-pool-provenance.md) evidence.

Each API key must receive explicit capability-ID grants; default grants remain empty. A grant authorizes the cataloged function, while the caller controls ABI arguments—including assets, paths, amounts, recipients, referral/borrow parameters, minimums, deadlines, and payable native value. No protocol-specific financial, slippage, recipient, price, health, or amount cap is added. Venus vToken and Compound V2 functions expose protocol return codes; successful EVM inclusion does not establish business-level success, and callers must interpret protocol return/event semantics. `approve(address,uint256)` is an independent grant: any spender and any `uint256` amount, including the maximum and zero, are permitted. It is never auto-granted with an action and has no matching-action, cleanup, or reset requirement. Catalog admission does not grant access. Existing capability IDs are preserved; owners should review prior grants and revoke/re-grant if they do not intend the broader scope. The 113 new IDs are not copied into existing API-key grants.

DeFi signing remains disabled; Openfort TEE remains the signing custody boundary. Unknown functions, ungranted capabilities, paused capabilities, and unsupported broad execution surfaces remain denied. IAM-only catalog/grant management, step-up for grant edits, API-key permissions, freezes, live pause and grant rechecks, session-key readiness, EOA isolation, and destination/billing gates remain independent controls. Generic transaction constraints and policies also remain: configured API-key spend budgets with UTC/native-wei accounting, structural limits of 10 interactions and 100 grants, Permit/Permit2 and NFT operator restrictions, destination protection, billing-debt policy, idempotency, and simulation. At 315 catalog entries, a key cannot hold all capability IDs under the existing 100-grant ceiling; clients should query/select only grants they need. The ceiling is unchanged and must not be raised or silently truncated. These separate controls may reject an otherwise granted function; they do not impose protocol-specific financial caps. No grants are automatically issued or backfilled.

Pause state is persisted in the singleton `defi_policy_state` row keyed by `global`. `DefiPauseService.setPaused(scope, paused, operator)` accepts structured `global`, chain, contract, or capability scopes and records actual changes transactionally. Pause remains an overlay on explicit grants. The database recheck cannot revoke an already signed or submitted operation.

Catalog construction validates fixed ABI identity and source/date provenance, merges family fragments, and deep-freezes the result. DeFi authorization checks exact catalog function/grant/pause state and canonical ABI decoding; it does not run separate financial templates or execution-evidence policy. Allowed events are exported after commit; denial audit follows rollback and must not mask the denial.
