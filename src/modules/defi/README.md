# DeFi capability operations and limitations

The assembled catalog contains 202 active, source-attributed function capabilities across seven supported mainnets: 179 actions and 23 independently grantable canonical `approve(address,uint256)` functions. It preserves the original 70 definitions, the 38-definition addition (36 actions, 2 approvals), and adds 94 definitions (91 actions, 3 approvals): 60 SushiSwap V2 calls (ten on each of Ethereum, Base, Polygon, Arbitrum One, Optimism, and BNB Chain; no Monad), four SparkLend calls, 27 Venus calls (five on each of five BNB markets plus two Unitroller calls), and independent Ethereum DAI / BNB BTCB and ETH token approvals. Savings sDAI/sUSDS and all three Rocket Pool candidates remain deferred. See the [capability matrix](../../../docs/defi-capability-matrix.md), [baseline provenance inventory](../../../docs/defi-research/simple-catalog-provenance.md), [DEX expansion evidence](../../../docs/defi-research/expansion-dex-provenance.md), [Sushi V2 evidence](../../../docs/defi-research/expansion-2-sushi-provenance.md), [Spark/Venus evidence](../../../docs/defi-research/expansion-2-lending-provenance.md), and [Rocket Pool evidence](../../../docs/defi-research/expansion-2-rocket-pool-provenance.md).

Each API key must receive explicit capability-ID grants; default grants remain empty. A grant authorizes the cataloged function, while the caller controls ABI arguments—including assets, paths, amounts, recipients, referral/borrow parameters, minimums, deadlines, and payable native value. No protocol-specific financial, slippage, recipient, price, health, or amount cap is added. Venus vToken calls return protocol error codes, not share/asset values; successful transaction inclusion does not establish business-level success, and callers must interpret protocol return/event semantics. `approve(address,uint256)` is an independent grant: any spender and any `uint256` amount, including the maximum and zero, are permitted. It is never auto-granted with an action and has no matching-action, cleanup, or reset requirement. Catalog admission does not grant access. Existing capability IDs are preserved; owners should review prior grants and revoke/re-grant if they do not intend the broader scope.

DeFi signing remains disabled; Openfort TEE remains the signing custody boundary. Unknown functions, ungranted capabilities, paused capabilities, and unsupported broad execution surfaces remain denied. IAM-only catalog/grant management, step-up for grant edits, API-key permissions, freezes, live pause and grant rechecks, session-key readiness, EOA isolation, and destination/billing gates remain independent controls. Generic transaction constraints and policies also remain: configured API-key spend budgets with UTC/native-wei accounting, structural limits of 10 interactions and 100 grants, Permit/Permit2 and NFT operator restrictions, destination protection, billing-debt policy, idempotency, and simulation. At 202 catalog entries, some keys cannot hold every capability under the existing 100-grant ceiling; clients should query/select only the grants they need. The ceiling is unchanged and must not be raised or silently truncated. These separate controls may reject an otherwise granted function; they do not impose protocol-specific financial caps. No grants are automatically issued or backfilled.

Pause state is persisted in the singleton `defi_policy_state` row keyed by `global`. `DefiPauseService.setPaused(scope, paused, operator)` accepts structured `global`, chain, contract, or capability scopes and records actual changes transactionally. Pause remains an overlay on explicit grants. The database recheck cannot revoke an already signed or submitted operation.

Catalog construction validates fixed ABI identity and source/date provenance, merges family fragments, and deep-freezes the result. DeFi authorization checks exact catalog function/grant/pause state and canonical ABI decoding; it does not run separate financial templates or execution-evidence policy. Allowed events are exported after commit; denial audit follows rollback and must not mask the denial.
