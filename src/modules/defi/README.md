# DeFi policy operations and limitations

This foundation intentionally ships with an empty catalog. No chain, contract, function, or typed-data capability is active. Typed-data signing is unconditionally denied. Do not populate the catalog without controlled security/product review of deployment identity, fixed ABI, validator, owner semantics, bounds, test vectors, reviewer, and policy revision.

Pause state is persisted in the singleton `defi_policy_state` row keyed by `global`. `DefiPauseService.setPaused(scope, paused, operator)` accepts structured `global`, chain, contract, or capability scopes and a UUID operator ID, bounded reason, and controlled reference. Scope keys are generated centrally and contract addresses are normalized. It serializes writes `FOR UPDATE`, audits actual changes in the same READ COMMITTED transaction, and exports only after commit; no-ops do not create audit events. This is an internal operator service, not a dashboard endpoint. The initial migration seeds the row once; missing state is a stable `DEFI_POLICY_UNAVAILABLE` outage and must not be auto-recreated.

`DefiCatalogService.listMetadata()` asynchronously returns `{ capabilities }` after a primary read of pause state. Active entries overlay to `paused` when any global/chain/contract/capability scope is paused; inactive entries remain `inactive`. Missing or unreadable state fails closed. The IAM catalog controller returns this object directly (do not wrap it a second time).

Catalog construction rejects duplicate identities/selectors, inconsistent hierarchy or ABI/signature definitions, and invalid active validators; copied catalog data is deeply frozen. Authorization requires a nonempty call batch and valid execution-owner address. Denial records contain a strict allowlist of safe identifiers and execution attribution, never calldata or signing material. Callers receiving `DefiPolicyDenial` must invoke `recordDenied` after transaction rollback; audit failure must not replace the denial. Allowed events written transactionally must be exported only after commit. The final database recheck does not eliminate the commit-to-chain-submission TOCTOU: pause/revoke cannot undo signatures, allowances, or already-submitted operations. No multi-instance freshness SLA or chain-level revocation is claimed.

For PostgreSQL cross-client lock evidence, set `DEFI_POLICY_PG_TEST=true` and provide `DATABASE_URL`, then run `npx jest --runInBand src/modules/defi/defi-pause.concurrent.pg.spec.ts`. The gated test takes no credentials from output and performs no persistent state mutation. Without that explicit environment, the concurrency test is skipped; deterministic mocks are not evidence of database locking.
