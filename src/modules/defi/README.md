# DeFi capability operations and limitations

The catalog contains 70 active, source-attributed function capabilities across seven mainnets: 52 protocol actions and 18 ERC-20 `approve` functions. Admission is exact to chain, contract address, selector, and fixed ABI. Provenance records official address/interface sources and dates; it is not a protocol safety, liquidity, runtime-identity, or transaction-success guarantee. Coverage is these named protocol/version entries only, not “most DeFi.” See [`docs/defi-capability-matrix.md`](../../../docs/defi-capability-matrix.md) and the [source provenance inventory](../../../docs/defi-research/simple-catalog-provenance.md).

Each API key must receive explicit capability-ID grants. A grant authorizes the cataloged function, while the caller controls its ABI arguments—including amounts, assets, recipients, borrow parameters, minimum output, deadlines, and payable native value where the function is payable. Protocol-native revert semantics remain unchanged. `approve(address,uint256)` is an independent grant: any spender and any `uint256` amount, including the maximum, are permitted. It is never auto-granted with an action and has no matching-action, cleanup, or reset requirement. Catalog admission does not grant access. Existing capability IDs intentionally have broader function-level scope; owners should review prior grants and revoke/re-grant if they do not intend the expanded authority.

Signing remains disabled. Unknown functions, ungranted capabilities, paused capabilities, and unsupported broad execution surfaces remain denied. IAM-only catalog/grant management, step-up for grant edits, API-key permissions, freezes, pause/revocation, session readiness, EOA isolation, and live authorization rechecks remain independent controls. Generic transaction constraints and policies also remain: configured API-key spend budgets, structural interaction/calldata/target limits, Permit/Permit2 and NFT operator restrictions, destination protection, billing-debt policy, and simulation. These separate controls may reject an otherwise granted function; they do not impose the removed DeFi-specific amount, recipient, approval, price, slippage, deadline, or funded-execution rules.

Pause state is persisted in the singleton `defi_policy_state` row keyed by `global`. `DefiPauseService.setPaused(scope, paused, operator)` accepts structured `global`, chain, contract, or capability scopes and records actual changes transactionally. Pause remains an overlay on explicit grants. The database recheck cannot revoke an already signed or submitted operation.

Catalog construction validates fixed ABI identity and source/date provenance, merges family fragments, and deep-freezes the result. DeFi authorization checks exact catalog function/grant/pause state and canonical ABI decoding; it does not run separate financial templates or execution-evidence policy. Allowed events are exported after commit; denial audit follows rollback and must not mask the denial.

**Validation status:** the assembled 70-active-function catalog passed Oracle Gate 1 attempt 3/3 after user-configured spend-budget findings were closed. This records the reviewed function-level authority set, not deployment/publishing approval or proof of a funded live UserOperation. Authenticated browser verification has not been performed.
