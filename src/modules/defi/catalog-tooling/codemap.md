# DeFi catalog tooling

Offline tooling for versioned source snapshots and the generated production fragment. `catalog-generator.ts` strictly validates source snapshots, canonical ABI identity, source references, scoped unresolved-chain assertions, and exact per-function admissions bound to each full canonical source JSON digest. Unadmitted source-derived functions stay inactive candidates. It preserves frozen baselines and deterministic output; historical v2/v3/v4/v5 assembly remains reproducible. V6 uses a fixed 27-path plan and `v6-identities.ts`, a literal source-path/family/version/chain/target/signature-to-capability-ID/ABI-hash map checked by the compiler (not a runtime fixture import). `admissions.json` binds all 134 functions to each canonical source digest, full selector/ABI identity, and any scope; assembly preserves the v5 baseline. `prepare-v6` remains read-only and emits no catalog/admission artifact. Bancor's nested family/chains/contracts/functions representation is normalized only for v6, retaining declared source-reference checks. The default catalog commands now target fixed v6 paths; explicit `:v5` commands retain the previous v5 workflow. Catalog admission is not financial-argument validation, deployment proof, or automatic API-key grant.
