# DeFi catalog tooling

Offline tooling for versioned source snapshots and the generated production fragment. `catalog-generator.ts` strictly validates source snapshots, canonical ABI identity, source references, scoped unresolved-chain assertions, and exact per-function admissions bound to each full canonical source JSON digest. Unadmitted source-derived functions stay inactive candidates. It preserves frozen baselines and deterministic output; historical v2/v3/v4/v5/v6/v7 assembly remains reproducible. V6 uses a fixed 27-path plan and `v6-identities.ts`; v7 uses an explicit five-path plan, `v7-identities.ts`, exact 28-binding admissions, and the complete 640-definition/15-scope v6 baseline to assemble 668 definitions. Current v8 adds exactly one Enso `routeSingle` root with one mandatory closed `enso-static-weiroll-v1` scope to the full immutable v7 baseline: 669 definitions, 646 actions, 23 approvals, 16 scopes. The v8 plan pins the raw v7 catalog hash `498c1c0d564472f2e585fba0ed3d46372f5f08e205f3e429163b7a1d9bedc570`, v7 manifest hash `0x32baaa989d966a12bf1b38f95d7bdc859ca2779b495ae27abbe40f0e95381533`, exact source path/digest, root full ABI and exact three child bindings. V8 admission requires both non-null scope and matching non-null hash; it cannot use generic scope admission. `prepare-v8` remains a fixed-input, read-only inactive projection; current v8 assembly/generation uses the explicit admission. The v8 catalog/generated module integration is not yet Gate 4 accepted. Historical v6/v5/v4 baselines and v7 profiles remain unchanged. Runtime imports only the generated production TypeScript module, never fixtures or source discovery. Current production catalog commands target v8; explicit v7/v6/v5 commands remain available. Admission does not validate financial arguments, deployment/runtime identity, funding, or customer grants.
