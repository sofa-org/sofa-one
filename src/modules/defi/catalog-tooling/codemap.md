# DeFi catalog tooling

The catalog tooling validates the single reviewed input at `data/defi-catalog/catalog.json` and generates/checks/diffs the deterministic static runtime module. `protocols-exporter.ts` also renders `frontend/public/protocols.json`, keyed by chain ID with `{ contracts, sign }`: active verified contract-call ABIs plus independent supported Polygon signing descriptors (ClobAuth, TypedDataSign and Batch), reusing runtime capability IDs. Signing-only Polygon is retained; other chains have empty signing arrays. The existing CLI generates/checks both outputs. The exporter strips `internalType` recursively while preserving standard tuple ABI structure and sorts chain IDs, addresses, protocol labels and signatures. Runtime never discovers source snapshots or plans. Public metadata grants no authority and carries no live pause state, domain/wallet/payload validation or executable-state assurance; all runtime controls remain independent.

The generator strictly validates catalog data, canonical ABI identity, source references, execution scopes, and explicit reviewed admissions. It produces deterministic static output. Historical research documents may describe prior snapshots but are not part of the current maintenance workflow. Neither admission nor generated catalog membership assigns grants or validates financial arguments, deployment/runtime identity, funding, or customer execution readiness.
