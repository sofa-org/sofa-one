# Code Map for /src/modules/defi

## Responsibility
Function-level DeFi catalog and API-key capability modes plus authorization of ClobAuth, CLOB V2 order and Polymarket DepositWallet Batch signing. The `polymarket:137:deposit-wallet-batch-sign:v1` capability allows arbitrary well-formed Batch calldata under strict typed-data bounds and zero native value; it is high privilege and can transfer assets or alter permissions. Batch call-target pauses are checked at preflight and atomic acceptance; global/chain/capability scopes pause the grant itself.

## Files and flow
- `defi.types.ts`: immutable execution, capability, match, authorization, denial, database and pause types.
- `registry/defi-manifest.types.ts`, `registry/defi-manifest.ts`, `registry/production-registry.ts`: reviewed manifest and generated production registry. The generated registry is the static runtime artifact; no source snapshot discovery occurs at runtime. Catalog definitions are not grants, and profiles are metadata rather than permissions. Catalog inclusion does not establish deployed runtime identity, funding, balances, liquidity, complete workflows, or financial safety.
- `catalog-tooling/`, `registry/generated/`, `data/defi-catalog/catalog.json`, `scripts/defi-catalog/`: single current offline catalog input, strict validation, deterministic generation, and diff. The catalog CLI has one current workflow; historical research records are not maintenance instructions. Catalog admission does not assign API-key grants. See [`scripts/defi-catalog/README.md`](../../../scripts/defi-catalog/README.md).
- `bundles/`: literal reviewed profile metadata exposed through the IAM/frontend-only read endpoint. Profiles are informational groupings, not grants; every capability remains subject to existing explicit grants and independent runtime controls. See [`bundles/README.md`](bundles/README.md).
- `coverage-tooling/`: pure offline coverage calculator/helpers and their synthetic tests remain available as isolated research utilities. The former snapshot-specific adapters/CLIs have been removed; `data/defi-coverage/` contains historical research reports only and does not participate in catalog maintenance or runtime authorization.
- `catalog-tooling/codemap.md`, `coverage-tooling/codemap.md`: implementation maps for deterministic catalog generation and isolated coverage calculations. Neither tooling directory participates in runtime authorization.
- `defi-catalog.service.ts`: injected catalog/manifest identity consistency, immutable copies, pause-aware metadata, and chain/capability lookup.
- `defi-grant.service.ts`: capability-mode-aware membership validation and transactional active/unpaused capability checks under the global shared pause lock.
- `defi-policy.service.ts`: chain/contract-local selector lookup for generic DeFi execution, mode-aware membership and pause checks, canonical ABI validation there, request commitment, final live-key/catalog/mode/grant/pause checks, and safe audit. DepositWallet Batch authorization separately validates exact typed-data shape, bounded calls/data, zero value, and per-call target pauses without decoding or allowlisting calldata.
- `defi-pause.service.ts`: structured scope keys, validated operator evidence, shared/exclusive global row locks, no-op suppression, READ COMMITTED atomic audit and after-commit export.
- `defi.module.ts`: catalog, grant, pause, policy and security-event providers; no DeFi evidence/RPC provider.
- `defi-catalog.service.spec.ts`, `defi-policy.service.spec.ts`, `defi-grant.service.spec.ts`, `defi-pause.service.spec.ts`, `defi-pause.concurrent.pg.spec.ts`: focused contracts and database concurrency coverage.
- `signing/polymarket-poly1271-envelope.ts`: normalizes 65-byte ECDSA recovery values `0/1` to `27/28` before constructing the Poly1271 envelope, preserves `27/28`, and rejects other recovery values. This is the current DepositWallet ECDSA verifier's format requirement, not a restriction imposed by ERC-1271 on all signature schemes.

## Security constraints
Active entries require verified source provenance, matching chain/contract/signature/ABI identity and fixed ABI selector uniqueness. ABI hash is Keccak-256 of recursively key-sorted ABI JSON (array order retained); catalog hash sorts capability IDs and commits only identity fields, not human copy or provenance dates. Every function must be authorized by current `all` mode or exact custom membership, remain unpaused and exactly match canonical calldata. Native value is a nonnegative uint256 and must be zero for nonpayable functions. Final authorization rechecks current API-key ownership, freeze/revocation/expiry, permission, mode/membership, pause, manifest identity and call binding under caller-owned READ COMMITTED transaction locks; it does no RPC. Denial audit excludes calldata/arguments. This function-level transaction catalog does not authorize signing; the separate ClobAuth exception uses its exact capability ID in custom mode (or `all` mode) and signing-policy checks.
