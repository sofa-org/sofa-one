# DeFi capability bundles

Static, versioned profile metadata for exact reviewed capability IDs. `production-bundles.ts` contains literal current profile memberships and literal expected fingerprints; `DefiBundleService` verifies every member, chain inventory, immutable version, and executable identity against the live reviewed manifest before serving metadata. Pause overlays only affect current availability and never mutate membership or fingerprints. Bundles are informational groupings, not grants: the dashboard performs the existing explicit full replacement, and every capability—including a multicall wrapper and each child—still requires its own grant.

The v6 baseline comprises 62 literal 1.0.0 profiles, preserving the original 33 objects byte-for-byte and appending 29 explicit phase2 selections for 134 unique candidate identities. Five phase3 profiles stage 28 exact aggregator identities after an immutable fixture of all 62 baseline objects. A separate Enso v8 worktree addition appends one literal root-only profile after an independent 67-profile/394-ID fixture from accepted v7 commit `445d448cca6fb4e8b2c2cf9d649c2a68f4122242`; it adds exactly the Enso `routeSingle` root ID, not its three child IDs. The current parallel v8 worktree also stages the 669-definition/16-scope generated catalog and the profile resolves against that manifest, but parent integration validation and Gate 4 remain pending; do not report these as accepted release totals. The candidate profile fingerprint is bound to the root's exact ABI and Enso scope hash. Exactly is split into two named Optimism market profiles and a separate Auditor enter/exit profile; the other 26 phase2 families each have one bounded selection. The 1inch profile contains 12 selected IDs, within the unchanged 100-grant limit; any request must still respect the existing ten aggregate decoded execution-node limit. Membership is a reviewed literal selection, never runtime family discovery, future-source scanning, or an automatic grant. Fingerprints bind exact manifest executable identity and scope. Approval authority remains independent and is neither included nor automatically paired. These profiles describe selected calls, not complete workflows, deployment inventory, funding, liveness, safety, eligibility, liquidity, or financial-argument guarantees. Gate 2 attempt 2 and final independent validation passed for the bounded 27-family addition; phase 3 has no accepted Gate/commit and is not 55-protocol completion or 90% market coverage.
