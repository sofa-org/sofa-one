Research snapshot: 2026-10-03. Requested chains were Ethereum (1), Base (8453), Polygon (137), Arbitrum One (42161), Optimism (10), BNB Chain (56), and Monad (143). This follow-up specifically examines the official docs' cpAMM deployment entry and the captured official app repository tree. No RPC, chain writes, transactions, funds, dependencies, or implementation changes were used. Admission requires an exact official chain-specific deployment plus fixed official ABI evidence; runtime identity, security audit, liquidity, execution or financial suitability are not required. The caller chooses paths, assets, amounts, recipients, deadline, slippage minimums, and native value. No automatic approvals or token wildcard are proposed.

## ABI and admission boundary

The initial retrieval passes were incomplete. The final pinned official SDK registry and interface evidence above admits exactly **60 direct function definitions**: ten methods on each of six separately recorded chain/router pairs. Scope excludes Sushi's RouteProcessor, Universal Router, generic `execute(bytes,...)`, multicall, permit, fee-on-transfer siblings, and quote/view functions. Matching Uniswap V2 signatures alone are not address or interface provenance.

Admitted direct-call fields remain caller-controlled: route `address[] path`, input/output quantities, bounds, recipient, deadline, and native value where the fixed ABI is payable. Canonical ABI, payability and explicit function grants still apply; this is not a financial-parameter safety endorsement. ERC-20 approval remains a separate explicit grant and is never automatic; this Sushi fragment adds no token approval capability.

## Retrieved primary-source record and concrete gaps

- Official GitHub API commit endpoint, retrieved 2026-10-03: [Sushi repository `sushi-labs/sushiswap` commit on `master`](https://api.github.com/repos/sushi-labs/sushiswap/commits/master). This is the current app repository and was not itself sufficient evidence of classic router deployment mappings/interface.
- The docs' official full corpus was retrieved at [`https://docs.sushi.com/llms-full.txt`](https://docs.sushi.com/llms-full.txt), HTTP 200, `Last-Modified: Wed, 30 Sep 2026 20:14:36 GMT`. Its `# cpAMM (SuhiSwap V2)` section states `## Deployments`, `### Factory`, and `### Router`, but only contains `<AddressTable data={SUSHISWAP_V2_ROUTER_ADDRESS} />`, not expanded chain/address rows. The same capture documents a separate `### Permit Router`; that family is excluded here. The docs are affirmative evidence the docs site maintains a cpAMM router deployment table, but not a usable captured address list.
- The captured app commit's recursive Git tree was subsequently parsed via HTTP JSON (`truncated:false`, 4,032 tree entries). Matching V2 entries exposed `apps/web/src/app/(networks)/(evm)/[chainId]/pool/v2/...` and the named Sushi V2 launchpad file; the pool UI imports `sushi/evm` symbols `SUSHISWAP_V2_ROUTER_ADDRESS` and `sushiSwapV2RouterAbi`, confirming the authoritative implementation moved to the SDK repository rather than defining addresses in the app. This is a source pointer only, not itself the router ABI/address source.
- Official SDK repository [`sushi-labs/sushi`](https://api.github.com/repos/sushi-labs/sushi), metadata retrieved 2026-10-03, identifies “Sushi library”. Its [`master` commit endpoint](https://api.github.com/repos/sushi-labs/sushi/commits/master) returned commit `5082d90dc76a87aaf731e9f3668384869ddf885b`, dated 2026-09-25, distinct tree `9c87bc3967b7ab593c48605f73298edbcaf62013`. Retrieved pinned raw registry source explicitly keys `ETHEREUM`, `BASE`, `POLYGON`, `ARBITRUM`, `OPTIMISM`, and `BSC` to the six addresses above. It also explicitly lists no Monad key. This is Sushi-maintained official config/SDK registry provenance, not runtime verification; do not extrapolate the same address to chains whose key is absent.
