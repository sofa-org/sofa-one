# Maple Pool V2 ordinary catalog update

This update adds six explicit, ordinary, scope-free Ethereum bindings: `deposit(uint256,address)`, `mint(uint256,address)`, and `requestRedeem(uint256,address)` on syrupUSDC (`0x80ac24aa929eaf5013f6436cda2a7ba190f5cc0b`) and syrupUSDT (`0x356b8d89c1e1239cbbb9de4815c39a1474d5ba7d`) PoolV2 targets. All are nonpayable and retain the exact named ABI fields and outputs from the verified source.

The source snapshot and plan are in `data/defi-catalog/updates/maple-pool-v2/`. The immutable baseline is `data/defi-catalog/updates/compound-v2-repay-behalf/catalog.json` (raw SHA-256 `897cc250972bf653f04dd2bf212b7807dcfcccceb96db1c14287c90336f1a947`, manifest `0x3a07fe42c4c3c9cfffffdaa2f8723c68e7f8f4a17125c2bd3aa0c96abbad08ef`). The source canonical SHA-256 is `12e758300b4e29b637eb3d3cf398c6e19d7c2f6bfccd94a4c6ed74d5ea5425b7`. Exactly six candidates are admitted, with no scopes or deactivations. Preview from the 696-definition baseline: +6/-0, zero prior authority, ABI, and metadata changes.

## Evidence and limits

Official Maple Ethereum mainnet documentation lists both addresses as PoolV2 products; its listed router is a different target. The pinned official Maple JS full ABI (`maple-labs/maple-js` commit `3d1d9fdf061d2d57de52808759ee1b9b8bc864ad`) exactly corroborates the selected ABI entries. Dated Etherscan verified-source carriers bind the same MaplePool source to each target; both extracted source blobs have SHA-256 `9f177bf35f38c6e3cee9d4c3ef23ddbb2708ad4f9b28a11a17c44484eb96d96f`. These source associations do not prove present runtime code, proxy/storage identity, constructor configuration, or deployment state.

The inspected bodies use a fixed configured asset and pool manager. `deposit` and `mint` check manager permission, mint to caller-selected `receiver_`, and transfer the configured asset from the caller. Approval is an independent prerequisite, not automatically paired. `requestRedeem` uses manager-configured escrow, owner shares and caller-selected sender, decreases applicable allowance, transfers LP shares to configured escrow, then calls the fixed manager request; its output is escrowed LP shares, not assets withdrawn or completed redemption. Manager permission, rounding/bootstrap rules, asset/escrow configuration, allowance, liquidity, and queue conditions may cause protocol-level reverts.

There are no platform amount, receiver, owner, or balance-equality restrictions. Zero/MAX uint256 and arbitrary receiver/owner arguments remain available where ABI-valid; Maple may reject them. No approval, permit, router, share transfer, withdrawal, completed redemption, admin helper, or additional asset is admitted. This is not a complete workflow, funded execution, liquidity, success, or financial-safety claim. Catalog inclusion creates no customer grants, profiles, scopes, or approval pairing.

IDs are `maple-pool-v2:v2:1:{lowercasePool}:{deposit|mint|request-redeem}`.
