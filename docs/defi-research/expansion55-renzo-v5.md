# Renzo Ethereum ordinary user-flow fixture (v5 expansion)

Official Ethereum deployment documentation (`https://docs.renzoprotocol.com/docs/contracts/ethereum-mainnet.md`, retrieved 2026-10-04; sitemap page modification 2026-06-26) identifies RestakeManager `0x74a09653A083691711cF8215a6ab074BB4e99ef5` and RenzoWithdrawalContract/WithdrawQueue `0x5efc9D10E42FB517456f4ac41EB5e2eBe42C8918`. These are canonical role addresses; no proxy status is asserted and proxy-only status is not an admission requirement. Official source-code documentation links the canonical repository (`https://docs.renzoprotocol.com/docs/contracts/source-code.md`). The ABI declarations are pinned to Renzo-Protocol/contracts-public commit `fc8c8e083852339fbddc7339287e54db77ff3959` (commit date 2025-12-10), source paths `contracts/RestakeManager.sol` and `contracts/Withdraw/WithdrawQueue.sol`.

Included functions (all VOID outputs): RestakeManager `depositETH()` and `depositETH(uint256 _referralId)` payable; `deposit(IERC20 _collateralToken,uint256 _amount)` and its referral overload nonpayable; queue `withdraw(uint256 _amount,address _assetOut)` and `claim(uint256 withdrawRequestIndex,address user)` nonpayable. ABI preserves original source `internalType` values. Each overload has a distinct selector-derived ID of form `renzo:v1:1:<target-lowercase>:<selector-without-0x>`; `v1` identifies the permission template, not an asserted deployed implementation version.

Queue `withdraw` opens a request for the sender; claim pays the request's user and is not caller-user-only, so a third party may trigger claim for another user. Queue operation is asynchronous and subject to protocol cooldown, fill, pause, and risk-oracle conditions; no instant liquidity or successful claim is promised. Deposit collateral eligibility and protocol checks are intrinsic. User-selected ABI-valid collateral, amounts, referral IDs, output asset, request index, and claim user remain free of platform financial/asset/owner caps. ERC-20 approval/funding is independent and not automatically coupled. Governance/admin/initializer/implementation paths, permits, generic execution and other operations are excluded.

`data/defi-catalog/v5/sources/renzo.json` is an inactive source candidate; `buildRenzoRegistry()` is an explicit test fixture, not production wiring or a grant. This six-method subset is not all Renzo support and establishes no implementation/runtime proof, funded execution, liquidity, economic success, or protocol-safety certification.
