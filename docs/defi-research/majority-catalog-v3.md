## Published exact-membership profiles

`src/modules/defi/bundles/production-bundles.ts` publishes nine literal `1.0.0` profiles: seven chain-specific Uniswap V3 Position Manager bundles and Ethereum/Base Morpho Blue bundles. Each exact capability ID array and expected fingerprint is reviewed into the source; the backend recomputes fingerprints against the current reviewed manifest at startup and fails closed on identity drift. Pause overlays do not alter identity: members remain visible and paused members make the whole profile unavailable.

The profile union contains 75 unique capability IDs (63 NPM and 12 Morpho); each of seven NPM profiles has nine literal members and each of two Morpho profiles has six. The largest individual profile contains nine grants. Ethereum and Base each inventory 15 capability IDs (9 + 6) across their two profiles. These counts do not justify changing the existing maximum of 100 grants per API key. Every NPM bundle contains its wrapper and all eight fixed child IDs; a selected child still requires the independently granted wrapper and child. Profiles are fixed `1.0.0` membership, not a selector and do not auto-expand when the catalog changes. Approvals are excluded from profiles and remain separately selected authority.

## Admission and execution-scope binding

Every source binding includes family, chain, normalized contract, signature, ABI hash, and exact capability ID. Snapshot admission uses recursively key-sorted canonical JSON (arrays retain order); source flags do not activate candidates. The two family ID versions are `uniswap-v3-position-manager:v3-npm` (preserving existing NPM IDs) and `morpho-blue:v1-callback-free` (new IDs). The source compiler rejects stale hashes, mismatched identity, missing/extra bindings, and source references not declared by the source snapshot.

Each Position Manager multicall scope binds the wrapper to exactly the eight reviewed child IDs/signatures/ABI hashes at the same chain and target: the five pre-existing position lifecycle functions plus `refundETH`, `unwrapWETH9`, and `sweepToken`. It does not include recursive multicall, NFT transfer/permit/approval, or unrelated methods. Runtime planning expands one level only and checks each selected child against exact same-target ABI binding, its independent grant, and pause state, with the final plan rechecked under existing transaction/pause/key locks and no RPC. One wrapper plus at most eight children remains within the existing ten-node ceiling. Native value is supplied once to the outer transaction and inherited by every selected child; existing key spending limits apply to the outer request, without a separate child budget. The scope does not bound ABI arguments or remove residual-balance risk.

Morpho `supply` and `repay` use `empty-callback-data-v1` at byte argument index 4; `supplyCollateral` uses index 3. These three scoped methods on each chain permit only empty callback data and do not provide a Morpho wallet callback handler. Amounts, market/asset choices, and other ABI arguments remain caller-controlled. Nonempty callback execution remains denied/unresolved.
