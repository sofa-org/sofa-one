## Global constraints and authorization behavior

- Reviewed token identity is chain-and-address exact, not ticker-based: only the exact registry USDC, USDT, and WETH records are candidates. In particular, Aave Arbitrum USDC.e and Compound Arbitrum native USDC are distinct assets; no WBNB→WETH or cross-chain aliasing is permitted.
- Approved template ceilings are **1,000 USDC raw units** and **0.25 WETH** (and 1,000 USDT raw units where otherwise applicable), aggregated by asset over the request. The active route is only USDC/WETH 500; no USDT, alternate fee tier, chain, or other route is enabled. These units are not a stable-dollar peg guarantee.
- Swaps require an independent input/output USD quote, positive fresh feeds, and `amountOutMinimum ≥ ceil(referenceOutput × 0.99)`; never assume USDC/USDT equals $1. Feed coverage is evidenced only for selected Ethereum, Optimism and Arbitrum pairs. Polygon/BNB do not gain a price path by substituting community feeds or BNB/USD. Swap deadlines must be future and no more than 120 seconds away. Evidence freshness is 30 seconds. Standard vault calls have no execution minimum-output argument and do not satisfy this policy.
- Aave has no execution deadline; deadline protection is a swap requirement, not a claimed Aave guarantee. Non-debt withdrawal preflight requires zero total debt but is only a point-in-time preflight, not an execution guarantee or an invented health-factor rule. Explicit full-repay `uint256.max` is rejected.
- For session-key batches, funded flows use the reviewed grammar: optional zero reset → exact positive approval → matching action → mandatory approval-to-zero cleanup. Live initial allowance/balance and action/spender pairing must pass evidence checks. EOA mode cannot submit positive approvals or funded actions. No automatic grants/dependencies are added.
- Existing access controls remain independent: DeFi catalog/grant management is dashboard IAM-only; grant changes use step-up; public transaction signing/send routes are not changed into dashboard routes. Grants are exact capability IDs, pause remains authoritative, and final authorization rechecks live grants. The capability/grant caps (100 IDs and 10 active API keys) are unchanged.
- Existing protected-destination checks can block ordinary DeFi for protected users; billing debt still requires its existing Calibur atomic evidence and fails closed when evidence is unavailable. Do not bypass either gate or claim this matrix establishes compatibility.
- Local fork evidence used an ephemeral fixture and direct Calibur owner-root path. A separate fixture pins Calibur runtime bytes and mocks evidence rounds; PG acceptance evidence is synthetic and structurally bound to authorization. None is live RPC verification or full Openfort signature, EntryPoint, bundler, session-key, or production UserOperation proof. The provider guarded RPC allowlist rejects paymaster stub/data: requests using `sponsorship: required` fail closed; the narrow trial supports only `sponsorship: none`. Calibur enforces exact runtime and owner delegation pins, with no legacy fallback. Private keys remain in Openfort; no real-fund test is implied.
